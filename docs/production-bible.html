The Advanced Production Bible

How to build a vertical video that demonstrates its subject rather than captioning it — the figure catalogue, the measured colour system, the mark specs, the sound contract, the script schema, and the verification chain that refuses anything which does not comply.

The one rule this document exists to enforce

No video is words on a colour field. Every video draws its subject in the middle third of the frame — a figure, a mechanism, a page being broken — and that figure is a decision written into the script, not a by-product of a template.

This is not a style guide. Every rule below is either enforced by a program that fails the build, or is a measurement with the measurement printed beside it. Where an approach was tried and rejected, the numbers that rejected it are given, so the rule can be argued with rather than merely obeyed.

I · The exhibit doctrine

The failure this replaces

The templates were type on a colour field. A SiteRoast said “slow first view” in large letters and never showed a page. A TechTip listed three steps and never performed one. That reads as a caption card, and a caption card is what a viewer scrolls past: the frame carries no evidence that anything is happening, so there is nothing to stop on.

Worse, it is invisible to every check. A caption card is a perfectly healthy render — the type animates, the variance is high, the end card is there, the file is the right length with sound on it. Nothing failed. That is why the rule needed a gate of its own rather than a note in a style guide.

The band

Every template stacks the same way: hook at the top, exhibit in the middle, payoff at the bottom. The middle is a shared constant, not a per-template guess: 

src/exhibits/registry.json → band: { top: 0.30, bottom: 0.74 }

It is one number because the verifier samples exactly those pixels. A band the layout did not actually honour would be a check passing on the wrong part of the frame — the most expensive kind of green tick. The top edge clears a three-line hook; the bottom edge clears the payoff block and the safe area the platforms overlay their own UI onto.

Two families, and why the distinction is load-bearing

Charts

Marks encode a measured quantity. Every length, angle and shade is value / scale. A chart-family figure requires real numbers in the script and the validator refuses prose in a numeric field.

Diagrams

Marks depict a mechanism the script already states, and take their labels from the script’s own lines. Nothing is measured, so nothing is claimed.

This split exists because of a component that was deleted from this codebase. TechTip once drew three bars whose heights were progress * (0.76 + index * 0.12) — a number derived from the frame counter and nothing else. It looked like a chart and measured nothing, which is worse than no chart: it invites the viewer to read a value that does not exist. The lesson is encoded as a type, not a convention.

Corollary — the honesty rule

If the script has no measurement, it does not get a chart. It gets a diagram, which is an equally strong picture and an honest one. Reaching for a bar chart to “look data-driven” is the failure mode, not the goal.

Where the figure comes from

  1. Authored. props.exhibit in the script. Always wins. This is the intended path.
  2. Assigned. scripts/backfill-exhibits.mjs writes one into the source scripts, choosing per day so the four posts six hours apart never draw the same picture. Its output is a file a human reads and edits.
  3. Derived. src/exhibits/derive.ts builds one at render time from the script’s own props. A floor, not a path — the validator requires an exhibit from week 33 on, so this is never reached in production.

The three cannot disagree: once the backfill has written a figure, the validator requires it and the derivation is unreachable. All three walk the same preference order in registry.json, and a unit test asserts the preference list and the per-kind permissions agree — the first version of this system silently stopped choosing the browser stage for SiteRoast because those two lists had drifted apart.

II · The figure catalogue

Seventeen kinds. The catalogue is src/exhibits/registry.json, and it is the only copy — the renderer, the plan validator and the pixel verifier all import it rather than keeping mirrors.

Choosing — in order

  1. Does the script state a measurement? → chart. Which one is decided by the job: one ratio → dial; magnitudes → bars; sentence-length categories → meters; a change → compare; unrelated headline figures → board; places → cartogram.
  2. Otherwise, what shape is the subject? Sequence → pipeline / timeline. Repetition → trace. Verification → checklist / radar. One-to-many → nodegraph. Code → code.
  3. Does the template have a native stage that already is the subject? Use it.
  4. Check the labels fit. A figure full of ellipses is worse than a different figure.

III · Colour, measured

Colour is assigned by the job it does, and the assignment is computed, never eyeballed. Four jobs, one rule each:

JobRule
IdentityCategorical. The validated pair below, in fixed order. Never cycled, never generated.
MagnitudeSequential. One hue, dark → light. Never a rainbow.
PolarityDiverging. Two poles, neutral midpoint. Not used in this series yet.
StateStatus. Reserved for pass / warn / fail, and always shipped with a glyph and a word.

The audit that changed the palette

The eight palettes pair a warm paper ink with one saturated signal colour. Those two were chosen to look good together as type, where shape carries the meaning. The moment two marks in one figure are told apart by colour alone the requirement changes: they must stay distinguishable to a red–green colourblind viewer — roughly one man in twelve scrolling past. Measured with the OKLab CVD model, three of eight did not:

Enforced

A plan may retint the type through props.theme. It may not touch theme.chart — the field is reinstated after the override spread in both resolveTheme and lookFor. Retinting type is a taste decision; retinting the marks that encode data would let a script hand a figure two colours measuring ΔE 4.8 apart with nothing noticing.

The sequential ramp

The obvious implementation is to fade the signal colour toward the ground. It is wrong twice, and both corrections were measured.

It is not one hue. These grounds are chromatic on purpose, so a step halfway between an orange signal and a purple ground is a muddy brown — the ramp measured 45° of hue spread on aubergine. A ramp whose hue moves is one the reader must decode instead of read. Scaling every channel by the same factor is exactly a lightness change and leaves hue alone: measured spread is now 1°.

Its floor was invisible. At a 0.18 floor the lowest cell measured 1.45:1 against its ground — a region carrying real data, rendered invisible. RAMP_FLOOR = 0.5 is the smallest floor clearing 2:1 on all eight grounds; the tightest, oxblood, lands at 2.30:1. 

rampStep(signal, t) = signal × (0.5 + t × 0.5)      // hue-preserving, visible at t=0

Text never wears the data colour

Marks carry the series colour. Labels, values and axis text wear ink tokens (paper / paperDim) — a light categorical hue is illegible as type, and identity is meant to come from the coloured mark beside the words. The single exception is a label sitting inside a filled mark, where the choice is made by measuring the fill’s relative luminance with WCAG’s own formula, not by thresholding the value that produced it.

IV · Marks, scale and layout

The scale factor — why the published mark specs are wrong here

Standard chart specs — a 24px bar cap, a 2px line, an 8px marker, a 2px gap — are written for a chart on a desktop screen where a CSS pixel is a pixel. This frame is 1080 wide and is watched on a phone roughly 390pt across, so a mark drawn at its literal spec arrives on the viewer’s eye at about a third of its intended size: a 24px bar becomes 9 points of ink, which is a hairline. 

MARK_SCALE = 1080 / 390 = 2.77          // src/exhibits/Figure.tsx
MarkReferenceThis frameRule
Bar / column thickness2466Cap it. The leftover in the band is air, not more bar.
Line weight26Round join and cap.
Marker / end-dot822Plus a surface ring where it overlaps.
Surface gap26One consistent width across a whole figure.
Hairline grid / axis13Solid, never dashed. Always recessive.
Rounded data-end411Rounded at the tip, square at the baseline.

One documented deviation

bars replaces the absolute 66px cap with a proportional one — a bar takes at most 62% of its band. The absolute cap assumes a chart sharing a dashboard with five others. Here the figure is the frame, so the proportional rule preserves the relationship the spec is actually protecting (“the leftover is air”) while letting the marks read on a phone.

The two spacers

Never draw a border around a mark to separate it. A stroke adds ink that is not data. Two mechanisms do the separating: a surface gap between touching marks, and a surface ring on dots and end-markers that cross something.

Labels — and why the usual advice is inverted here

The standard rule is label selectively: label the endpoint, the extreme, the one series the story is about, and let the tooltip and table view carry the rest. That rule assumes a reader who can hover.

Video amendment

There is no tooltip, no legend box, no table view and no hover. The direct label beside a mark is the only channel left when colour fails, so every mark is labelled, and the figure’s panel header names what is being measured. A legend box would restate the header and cost the space the marks need.

Hard prohibitions

  • Never a second y-axis. Two measures of different scale are two figures, not one figure with two rulers. This is the single most common way a chart lies.
  • Never generate a hue for an extra series. Fold the tail into “other”, facet, or cut series.
  • Never colour by rank. Colour follows the entity. A filter that changes the series count must not repaint the survivors.
  • Never clip a label with overflow:hidden. If it does not fit, move it outside the mark or choose a different figure.
  • Never mark state by colour alone. Verdicts ship with a glyph and a word.

V · Motion

Arrival, not appearance

A figure’s panel rises and settles on a spring rather than fading. A fade reads as a slide transition; a physical arrival reads as an object entering the frame, and that is the difference between a deck and a video. The marks follow the panel, and a counting number rides the same spring as the mark it labels — a value that finishes before its bar does reads as two unrelated animations.

Motion is a variation axis

Every campaign video walks an 8 × 7 × 6 = 336-combination space of palette × typeface × motion signature with a stride coprime to the space, so 120 videos are distinct by construction rather than by luck. A signature changes entrance direction, stagger, spring damping and mass, and the backdrop’s grid scale and skew — so two videos sharing a palette and a typeface still do not produce matching frames. The figure kind rotates on the same ordinal, so consecutive videos on one template never draw the same picture.

The performance budget is real

These render on a two-core runner through a software GL path. The rules are not stylistic:

  • No full-frame blur. Glows are radial gradients. A full-frame filter: blur() costs more than every other layer combined.
  • Rasterise once, translate thereafter. Animating a gradient’s position repaints 1080×1920 twice a frame: measured 0.43 s/frame → 1.21 s/frame. Animate transform so each frame only composites.
  • Grain is a 256px tile, not a full-frame filter. An feTurbulence over two million pixels was roughly three quarters of total render time.
  • Line work is SVG. The rasteriser is good at it.
  • No Math.random in a render. Every variation is a pure function of the video id, because renders are retried and a retry that produced a different video would invalidate the stored fingerprint.

React rule that bites here

Every figure draws a list of marks, so timing is computed inside a map. Read the frame once at the top of the component and pass it down to pure helpers (arrival(theme, from, frame, fps)). A hook called in a loop is a hook whose call order changes with the data.

VI · Sound

With no voiceover, the audio track is not decoration — it is the performance. Two requirements, and both are made unfalsifiable rather than merely stated.

No voice

Every sound in the series is synthesised by this repository: bed layers and one-shot cues built by scripts/audio/. A cue names a generated one-shot, never a file. 

// scripts/exhibits.mjs → voiceProblems()
props.voiceover | narration | vo | speech | tts   → rejected
score.cues[].sfx containing "." "/" or "\"        → rejected  (that is a file, and a
                                                    file is audio this repo did not make)

The check is on the script, not the render, because by render time the decision has already been made. It is the only way a voice could reach the mix, so it is closed at the only place it can be closed.

Low volume — a band, not a floor

The master pass targets −23 LUFS at −2 dBTP. Verification checks a band, measured as mean RMS in dBFS: 

QUIET_FLOOR_DB   = -45     // below this: a track with effectively nothing on it
QUIET_CEILING_DB = -14     // above this: an unmastered mix at full level
observed on real mastered renders: -29.4 dB

The ceiling is the important half and the one a floor-only check misses entirely: it catches an unmastered mix going out at full level under a viewer’s thumb at two in the morning. Measured as RMS rather than LUFS because that needs no filter build — Remotion ships ffmpeg with --disable-filters and volumedetect is not among the few re-enabled.

The score model

  • Bed — layers that enter and leave on named frames. One layer per beat is the house pattern.
  • Cues — one-shots on exact frames, with optional pitch escalation. Pitch rising across a build is this series’ substitute for narration.
  • Hard silence — cut every layer for a full beat before a payoff. Used on nearly every script. This is why the frame verifier reports stillness rather than judging it: deliberate stillness is a device here, and a check that failed it would fail the videos following the brief most closely.
  • A script that transcribes no score gets the template’s documented bed behaviour, so no video is ever silent by accident.

VII · The script schema

Scripts are authored in plan-source/campaign/w<n>.json. Ids, day numbers, eyebrows, runtimes and the week block are all derived by scripts/build-campaign.mjs — never written by hand, because that is what validators check hardest and humans are worst at.

Gate 4, in detail — and the honest limit of it

The tempting wrong answer

Look at the pixels and recognise the figure. It does not work, and this was measured rather than assumed. The same script rendered before and after the exhibit layer scored 86% and 81% on the “how much ink is continuous mark” statistic — the text-only version scored higher. Large display type produces runs just as long as a bar does. Erosion and panel-contrast variants separated no better: 4.8% vs 6.3%, and 39% vs 84% with a text-only FounderStory scoring 100%.

A gate that does not separate the two cases is not protecting anything. It is a number that passes, which is worse than no number.

What works is a chain of individually provable steps:

  1. The script names a figure that exists, is allowed on that template, and has every field it needs. Proved by reading the plan against the catalogue.
  2. The renderer was handed exactly that script. Proved by comparing the props file the render used against the plan item, canonically — key order cannot cause a false failure, and the injected videoId is checked against the item id separately because it seeds palette, typeface, motion and musical key.
  3. Renders are a pure function of their props. The project already depends on this: a retry producing a different video would invalidate the stored fingerprint.
  4. Therefore the video contains that figure.

The pixels are still inspected, and still gate — for what they can actually prove. inspect-band.mjs decodes only the band and asks whether it is occupied, alive and held. That catches what a props comparison cannot: a font that never loaded, a component that threw, a figure that vanished after six frames.

Band checkFloorWorst realCatches
Settled ink coverage3%6.6%An empty middle third.
Frames the band changes on426A figure that is a still image.

Calibrated against seven real renders across every template. The low end of each is a genuine video, not a bad one — 6.6% is a sparse radar, 74% is a LogoLadder clearing its own stage during a scripted freeze. Every floor sits well under the worst real measurement, deliberately: a false positive blocks a publish and needs a human at 3am, while what these catch are gross failures measuring near zero, not near the floor.

State it plainly

The pixel gate proves the band is occupied and alive. It does not prove which figure is in it. That guarantee comes from the plan contract plus deterministic rendering — a proof, where a classifier would be a guess.

IX · Working practice

Authoring loop

  1. Write the script in plan-source/campaign/w<n>.json, including props.exhibit.
  2. npm run exhibits -- --check — proposes figures for anything missing one, without writing.
  3. npm run campaign — rebuilds plans/ from source.
  4. npm run validate — all five plan-side gates.
  5. npm run studio — look at it. Or npx remotion still src/index.ts <Template> out/probe/x.png --props=<file> --frame=150 --scale=0.4 for a fast single frame.
  6. npm test — 162 tests, including the catalogue-consistency checks.
